# A field guide to Linux binary analysis and ELF

An ELF (Executable and Linkable Format) file is a static plan for a program's live presence in memory. The kernel maps its segments into virtual memory, the dynamic linker resolves library symbols, and the structures generated by the compiler take effect at runtime. Custom loaders and packers can reproduce parts of this process in user space to unpack code in memory.

`execmap` is an English reference to reverse engineering, connecting static bytes on disk to runtime behavior through documented system mechanisms and practical laboratories.

## Hands-on laboratories

Learn with small experiments you can compile and run in your own terminal:

- **[A first GDB investigation](laboratuvarlar/gdb-ilk-inceleme.md)**: Read arguments at function entry, follow the instruction that writes memory, and verify the return value.
- **[Branches and pointers](laboratuvarlar/dallanma-ve-pointer.md)**: Compare the data flow of the same condition and pointer target under `-O0` and `-O2`.
- **[Memory permissions](laboratuvarlar/bellek-izinleri.md)**: Observe an anonymous mapping changing from RW to RX, and why a permission change does not prove execution.
- **[Symbol selection](laboratuvarlar/sembol-secimi.md)**: Interpose on a call with `LD_PRELOAD` without modifying the executable.
- **[Debug information](laboratuvarlar/debug-bilgisi.md)**: Separate DWARF data, strip the working binary, and reconnect it to GDB with `.gnu_debuglink`.
- **[Compiler differences](laboratuvarlar/derleme-farklari.md)**: Examine inlining, stack layout, and loop transformations under `-O0`, `-O2`, and `-Os`.
